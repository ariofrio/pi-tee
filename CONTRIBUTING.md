# Contributing

Use the locked Node 24 workspace. Read [SECURITY.md](SECURITY.md) before changing policy, transport, model routing or verification reporting.

Test through the native provider and transport interfaces. Observe prompt transmission at the external SDK/network seam; do not mock policy or message-conversion internals. Add a failing test for security behavior before implementation. Keep provider differences in their adapters and common enforcement in the shared library.

Run `npm ci --ignore-scripts`, `npm run check`, `npm run smoke`, and `npm run smoke:packages` (which may download dependencies). [CI](.github/workflows/ci.yml) runs them on every push to `main` and pull request, with the Go helper's `gofmt`, `go vet` and `go test` and the Bun-specific tests; tests that need private evidence fixtures skip there, so run them locally when you have the fixtures. The tarball check establishes package loading, login and SDK separation, not qualification of a newly resolved verifier dependency set. Catalog and attestation smokes are optional live checks with no inference. Never put keys or provider payloads in tests, logs or examples. A mocked verifier result does not qualify a deployment for production.

Changes to SDK/Pi versions require reviewing error/retry behavior, final payload coverage, key rotation, API/loader compatibility and the explicit trust disclosures. Public-build policy permits authenticated releases from its named publisher/workflow identities without maintained deployment pins. Do not silently expand those authorities or treat provider release tags as independent approval. Do not enable a production profile without all hardware, serving-path, runtime, artifact-chain and review gates. See the [current design](docs/design/architecture.md).

Changes to the WebAssembly verifiers go through `npm run build:wasm`; commit the [CI-built artifacts](docs/procedures/verifier-builds.md) and keep `npm run check:nvidia` passing. Update the relevant package README and [CHANGELOG.md](CHANGELOG.md) with behavior and validation. Registry publication and external submissions require the project owner's approval.

User docs start at the [quick start](docs/quick-start.md), [security model](docs/security-model.md), [provider guide](docs/providers.md) and [reference](docs/reference/README.md). Algorithms belong beside their source; design rationale, qualification procedures and dated evidence have [separate homes](docs/procedures/README.md). Update the evidence index when dependencies, authorities, floors or adapter behavior change; old results are not a new qualification.
