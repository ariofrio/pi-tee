# Tinfoil Intel candidate

`PI_TINFOIL_POLICY=sdk PI_TINFOIL_ROUTE=direct-intel` selects the fixed `gemma4-31b` worker `gemma4-31b-inf8-0.tinfoil.containers.tinfoil.dev`. This is an experimental SDK-policy route, with stronger local hardware appraisal, not an enabled Approved profile. It currently supports the tested macOS ARM64 development environment with explicitly installed local helpers.

[Appraisal](../packages/tinfoil/src/intel-appraisal.ts) generates a fresh nonce, authenticates the TDX quote with locally embedded Intel policy, checks the exact CPU-bound NVIDIA evidence with the local manufacturer verifier, then releases the quote-bound TLS/HPKE public keys to the [encrypted transport](../packages/tinfoil/src/direct.ts). Attested SPKI authenticates the actual TLS 1.3 inference socket before the API key or EHBP ciphertext is sent. The request sends once; rotation, reconnect/retry by the direct transport and fallback to another worker are not accepted. An encrypted random `cache_salt` uses the pinned vLLM engine's cache-namespace field. This does not establish all runtime cache behavior.

The native route passed the complete [actual Pi suite](../scripts/live-pi.ts) on 2026-10-07: compiled loading, native secret login, stored-key precedence, completion/usage, Unicode tool execution/result follow-up, reasoning/final text and RPC cancellation. A separate `--cancel-stream` run passed after a live text delta without the response-consumption barrier. Neither measures when the remote engine stops generation.

The [combined research probe](../scripts/research/tinfoil-intel.mjs) also passed fresh CPU/GPU appraisal, rejected forged GPU evidence, a wrong GPU nonce and a mode-field substitution with NVIDIA signature-error result `508`, and completed one synthetic encrypted inference with usage. [Real CPU evidence tests](../tools/tinfoil-cpu/mutation_test.go) reject altered quote signatures, nonce, measurements, TLS/HPKE keys and GPU bytes even when untrusted section hashes are recomputed. A [local-helper regression](../tests/tinfoil-intel.test.ts) rejects an unpinned executable before any attestation request.

Appraisal first requires the configured Docker endpoint to be the local Docker Desktop or OrbStack Unix socket under the current user’s home directory. TCP, SSH and other sockets are rejected before evidence collection. Both container execution and cleanup explicitly use that checked socket, so a later context switch cannot redirect the appraisal. This is a local installation/OS assumption, not cryptographic proof that a Unix socket never forwards traffic.

The wrapper writes public GPU evidence and private copies of the verified NVIDIA CLI/library into an owner-only temporary directory next to the configured CPU helper, derives the loader aliases there, and removes it after appraisal. The container uses those copies rather than reopening mutable source artifacts. It buffers helper claims in memory and exposes no raw reports, prompts, responses or keys in normal status output. Cancellation closes the verifier process, removes its named container and rejects inference; public manufacturer verification traffic may already have occurred.

## Local setup

The public-build CPU helper and NVIDIA execution image can now be built with the packaged `pi-tinfoil-setup --directory ABSOLUTE_PATH` command. It requires Go (the build selects toolchain 1.26.6), Docker/buildx and the supported macOS ARM64 environment. It downloads six fixed public artifacts, checks exact sizes/SHA256, builds the locked CPU source and checks its executable hash, then constructs the GPU image from the pinned Ubuntu base plus five pinned dependency archives. Package extraction does not execute maintainer scripts. The image build uses no RUN network access, epoch-zero timestamps and no provenance/SBOM attachments. Its exported OCI tar must match SHA256 `48d8202ed8b45bca8e1f8a7bdb189130d2e519ea1425744603cc9bfa41e7a1d0` before loading; the loaded image digest is also checked. Two clean builds with Docker 29.4.0/buildx 0.33.0 produced identical tar bytes. A different build result fails closed. [Setup command](../packages/tinfoil/src/setup.ts), [recipe](../tools/tinfoil-gpu/Dockerfile).

This first public-profile setup supports macOS ARM64 with local Docker Desktop/OrbStack. It is not a cross-platform or arbitrary-builder-version reproducibility claim. Other client platforms retain explicit SDK routes. The NVIDIA binary remains a manufacturer-distributed artifact, not independently rebuilt source. The frozen CPU helper is separately built from its [locked source](../tools/tinfoil-cpu/README.md).
Set absolute paths `PI_TINFOIL_CPU_VERIFIER` to the executable and `PI_TINFOIL_NVAT_DIR` to the extracted NVIDIA archive directory. Set `PI_TINFOIL_ROUTE=direct-intel` and explicitly choose SDK policy. Use Pi's existing `/login tinfoil` or a private credential file. The native extension never downloads tools or accepts a caller-supplied hardware policy.

## Remaining approval gates

The fixed boot values were initially acquired from authenticated provider reference material. Freezing them removes ongoing provider selection, but does not independently approve their source or build. [Workload qualification](tinfoil-workload.md) records the recomputed boot-artifact trace, checked runtime source paths and remaining work. The guest/engine/weights/key-custody inventory, compute-channel/reset lifecycle, all plaintext-capable processes and runtime mutation/egress behavior still need complete qualification and an independent implementation review. NVIDIA file appraisal authenticates the CPU-bound device report; it does not alone establish the later execution path. [Full gates](../SECURITY.md).

NEAR's shared-key/session contract and Pi's physical-dispatch guard are separate requirements. Neither this route nor its hardware passes enables Approved policy or claims a closed whole-session trust set.
