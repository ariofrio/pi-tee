# Tinfoil public-build serving contract

This contract covers direct Tinfoil workers serving the models below with the `tinfoil-vllm-v1` runtime profile. It accepts software updates from the named public publishers. It does not require reviewing or rebuilding each release independently. Production admission awaits independent review. [Appraisal](../packages/tinfoil/src/worker-appraisal.ts), [session](../packages/tinfoil/src/public-session.ts), [review requirements](../CONTRIBUTING.md).

| Model | Workload publisher | Observed deployment (2026-10-07) |
| --- | --- | --- |
| `gemma4-31b` | `tinfoilsh/confidential-gemma4-31b` | Intel TDX, one Hopper GPU in SPT mode. Its AMD Genoa workers are rejected: their firmware lacks the AMD-SB-3020/3027 fixes. |
| `deepseek-v4-1-flash` | `tinfoilsh/confidential-deepseek-v4-1-flash` | Intel TDX, eight Blackwell B200 GPUs in MPT mode |
| `glm-5-3` | `tinfoilsh/confidential-glm5-3-nvfp4` | AMD SEV-SNP, eight Blackwell B300 GPUs in MPT mode |

The deployment column describes what was observed, not a pin. Either CPU platform and any GPU configuration the policy below admits are accepted for every model. Other Tinfoil models are reachable only through a decrypting router that does not enforce this policy. [Model coverage](design.md#provider-assessment).

Independent Opus 5.5 reviews cover the [combined verifier/session](reviews/pi-tee-public-session-opus-review.md), [pinned local setup](reviews/pi-tee-local-setup-opus-review.md) and [routing/enablement](reviews/pi-tee-enablement-opus-review.md). Their scopes and live-test limitations are recorded in those reports. A [review of the multi-model, SEV-SNP and TLS changes](reviews/pi-tee-multimodel-snp-tls-opus-review.md) found the firmware-floor, engine-image and TLS issues fixed since; a separate review covered the WebAssembly verifiers and NVIDIA reference-manifest patch. Both must re-check the fixes before production admission.

The public publishers are provider-operated authorities accepted under this policy. The cloud/inference operator's deployment instructions, DNS, catalogs, registry/CDN responses and ATC delivery do not separately authorize code, measurements or serving keys. Delivery can withhold service and expose traffic metadata. Signed roots and fresh appraisal constrain what can be accepted. Freshness lasts seven days with five minutes of future skew; a still-endorsed older release is allowed. This is neither immediate revocation nor a newest-release guarantee. [Artifact authentication](../packages/tinfoil/src/public-build.ts), [freshness verification](https://github.com/tinfoilsh/tinfoil-go/blob/23734b7c6b9acf5359087412b03ebb524c2fb2f1/verifier/provenance/freshness.go).

## Plaintext, keys and runtime

The intended remote plaintext closure includes the measured kernel/PID 1, boot service, shim, container manager, rootful Docker/containerd/OCI runtime, NVIDIA driver and helpers, and the authenticated inference engine and its libraries/tokenizer/templates. Inside the engine image, two Tinfoil components also see plaintext: the [`inference-sidecar`](https://github.com/tinfoilsh/inference-sidecar) reverse proxy, which DeepSeek's image runs in front of vLLM for usage metering and padding, and the [`tinfoil_usage`](https://github.com/tinfoilsh/tinfoil-usage) vLLM middleware, which GLM-5.3's image loads. Both are pinned by digest or checksum in the publisher's Dockerfile and trusted through the workload publisher; the client does not authenticate their own provenance. The profile admits only `vllm serve`, optionally behind that sidecar, as the image's process, and only a fixed set of inherited environment variables. Privileged guest code belongs inside this trusted software closure: mode `0700` does not exclude a root-capable process. One engine container and no separate sidecar container or decrypting router are admitted by the configuration profile. Source links in this contract cite guest `v0.11.0`; the cited mechanisms are present in the `v0.12.0` and `v0.14.6` guests the other models run, and every accepted guest release is trusted to preserve them. [Runtime constraints](../tools/tinfoil-public-build/runtime.go), [service startup](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/pid1/main.go), [private/public paths](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/boot/paths.go).

The checked guest generates a fresh P384 TLS key and a new HPKE identity in its private RAM filesystem at boot. The HPKE file is reused within that boot, not provisioned across workers. The private tree, Docker data and containerd state are RAM-backed; the public container mount excludes serving keys. There is no profile-authorized vault/KMS/key export recipient. Future authenticated releases are trusted to preserve this custody contract; hashes authenticate the selected implementation, while publisher trust supplies its behavior. [Identity generation](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/boot/identity.go#L26), [RAM setup](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/pid1/runtime/setup.go#L125), [Docker state](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/image/rootfs/etc/docker/daemon.json), [containerd state](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/image/rootfs/etc/containerd/config.toml).

The signed deployment subject must equal the CPU-accepted signed predicate. Authenticated guest/configuration roots, the exact non-debug command line and the constrained runtime select the serving environment. The client recomputes the quote-bound boot measurement from the authenticated kernel, initrd and command line: RTMR1/RTMR2 on TDX, or the whole launch digest with the pinned OVMF on SEV-SNP. The read-only guest and each declared model pack use dm-verity; the engine uses its authenticated OCI digest. Runtime downloads must obey those roots. Model attribution here means publisher-authorized model/tokenizer bytes, not proof that the model's original developer uploaded them. [Subject binding](../tools/tinfoil-public-build/release.go), [TDX boot calculation](../packages/tinfoil/src/boot-measurements.ts), [SEV-SNP launch digest](../packages/tinfoil/src/snp-measurement.ts), [guest mount](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/initrd/main.go#L67), [model mounts](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/boot/models.go#L83).

The production container manager opens no configuration replacement listener and records a one-shot boot marker. The shim enables inference only after boot succeeds. Modules cannot be loaded or unloaded after initialization. The engine has read-only root, dropped capabilities, bounded RAM caches and no external network; the shim dials fixed address `172.31.255.2`, without DNS. The guest's egress-capable services remain trusted guest processes. Request/output logging flags, remote-code loading and engine egress networks are rejected by the profile, which also checks the value of every allowed engine flag and environment variable. [Container manager](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/containers/main.go#L68), [shim gate](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/shim/main.go#L110), [module lock](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/pid1/hardening/module_lock.go), [upstream](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/shim/upstream.go), [closed network](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/containernet/network.go), [egress](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/egress/main.go#L42).

The production kernel build selects a null console and disables virtual/serial consoles. On SEV-SNP the pinned OVMF is a debug build that writes firmware messages to the host-visible serial port; it runs before the kernel and handles no inference data. Private guest logs are not made confidential merely by sanitizing errors. The claim depends on this console/build contract and the absence of an admitted transcript-export sidecar. [Kernel selection and config check](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/nix/kernel.nix#L12), [production console](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/kernel/config.d/20-production-console.config), [serial exclusions](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/kernel/config.d/20-console-common.config).

## GPU channel and reset contract

Fresh CPU report data authenticates the exact GPU evidence and serving public keys. The client locally verifies NVIDIA's report for every GPU the release declares and requires one claim per device, a single supported hardware model, distinct devices and the authenticated protected mode. [Appraisal](../packages/tinfoil/src/worker-appraisal.ts), [version policy](../packages/tinfoil/src/gpu-policy.ts), [mode interpretation and signed-field negative](tinfoil-gpu-runtime.md).

| Hardware model | GPUs | Required mode | Minimum driver / VBIOS |
| --- | --- | --- | --- |
| `GH100 A01 GSP BROM` (Hopper) | 1 | SPT | `595.71.05` / `96.00.D0.00.03` |
| `GB100 A01 GSP BROM` (Blackwell) | 1–8 | SPT for one, MPT for several | `595.71.05` / `97.00.D9.00.35` |
| `GB110 A01 GSP BROM` (Blackwell) | 1–8 | SPT for one, MPT for several | `595.71.05` / `97.10.64.00.0C` |

In multi-GPU confidential computing, NVLink and NVSwitches are outside the trust boundary and the GPU copy engines encrypt NVLink data. PPCIe instead trusts NVLink plaintext and is rejected; Hopper multi-GPU would need it. [NVIDIA multi-GPU trust boundary](https://docs.nvidia.com/attestation/attestation-client-tools-ppcie/latest/ppcie_introduction.html). Each floor is the oldest version seen with signed, unrevoked references when the model was qualified. Upgrades also require matching signed golden references and revocation checks; the floors do not claim every newer version is vulnerability-free.

NVIDIA's manufacturer contract supplies SPDM authentication, protected CPU–GPU transfers, key isolation, reset/scrubbing and persistence semantics. The checked driver authenticates SPDM, derives channel keys, encrypts/authenticates UVM bounce transfers and enters a fatal state when the channel fails. Readiness cannot be restored after that failure; the guest module lock prevents recovering by reloading the driver. A new guest boot generates new serving keys and needs new client appraisal. These are manufacturer/publisher implementation contracts supported by source and signed live evidence, not measurements of a physical reset or every CUDA transfer. [Driver/source trace](tinfoil-gpu-runtime.md#driver-execution-and-failure-paths), [NVIDIA protected transfers, pages 11–13](https://docs.nvidia.com/nvidia-secure-ai-with-blackwell-and-hopper-gpus-whitepaper.pdf), [NVIDIA reset/persistence, page 28](https://images.nvidia.com/aem-dam/en-zz/Solutions/data-center/HCC-Whitepaper-v1.0.pdf).

## Client session and limits

Each dispatch rediscovers the model's workers from untrusted delivery metadata, probes which accept a TCP connection on port 443, and appraises at most four reachable candidates in random order, trying the last healthy host first. Each candidate gets a fresh challenge and full appraisal, and a failure relaxes nothing for the next. Requests address the logical endpoint `https://direct-worker.tinfoil.invalid/v1`; the transport dials only the host just appraised. [Discovery and selection](../packages/tinfoil/src/public-session.ts).

Before an inference send, an owned session binds canonical model, authority-policy digest, authenticated release/artifact digests, current freshness bounds and the quote-bound TLS/HPKE keys to the transport. TLS 1.3 SPKI is checked on the actual socket before credentials or EHBP ciphertext. The direct transport sends once, rejects rotation/reconnect/fallback and uses a fresh encrypted cache salt. Streaming output and tool calls pass authenticated decryption with bounded bodies. [Transport](../packages/tinfoil/src/direct.ts), [TLS binding](../packages/core/src/pinned-tls.ts), [payload boundary](../packages/core/src/transport.ts).

The local cache retains authenticated immutable artifacts and deterministic verifier results, not CPU challenges, GPU verdicts, endpoint keys or freshness acceptance. Each dispatch obtains fresh evidence. [Cache regression](../tests/public-build-chain.test.ts). The actual Pi suite and live-delta cancellation passed for all three models on the experimental `direct-public` route, which runs this appraisal, under Node and the Bun-compiled Pi binary. [Evidence](portable-verification.md#evidence), [harness](../scripts/live-pi.ts).

This is a contract for these provider dispatches. Whole-session protection remains unestablished because other providers, extensions, tools, compaction and fallback need Pi-level enforcement. Availability, traffic analysis, billing truth, output correctness, undocumented side channels and local-machine compromise are outside the claim. NEAR has separate deployed shared-key/session/KMS/runtime gaps. [Pi and NEAR boundaries](design.md).

Revocation is only as fresh as the collateral a worker presents. The worker chooses which still-valid AMD CRL or Intel collateral to include, so a newly revoked key or TCB can be accepted until that collateral expires: about 48 days for AMD's CRL and 30 days for Intel's. TLS key exchange is post-quantum hybrid (`X25519MLKEM768`) under Node and classical under Bun 1.3.13; the EHBP body encryption is classical X25519 HPKE in both.

`closedTrustSet: profile-declared` identifies this declared publisher/manufacturer closure. It does not claim an independent proof that every accepted software release behaves safely. New protocol/schema fields, GPU families or configurations outside the constrained profile, a new workload repository and SEV-SNP firmware changes require a client policy update; an authenticated compatible artifact update does not.
