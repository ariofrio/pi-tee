# Tinfoil public-build serving contract

This contract covers one direct Intel TDX worker, one Hopper GPU in SPT mode and the `gemma-single-gpu-v1` runtime. It accepts software updates from the named public publishers below. It does not require reviewing or rebuilding each release independently. Production admission is paused while the GPU verifier is replaced and requalified. [Implementation](../packages/tinfoil/src/intel-appraisal.ts), [review requirements](../CONTRIBUTING.md).

Independent Opus 5.5 reviews cover the [combined verifier/session](reviews/pi-tee-public-session-opus-review.md), [pinned local setup](reviews/pi-tee-local-setup-opus-review.md) and [routing/enablement](reviews/pi-tee-enablement-opus-review.md). Their scopes and live-test limitations are recorded in those reports.

The public publishers are provider-operated authorities accepted under this policy. The cloud/inference operator's deployment instructions, DNS, catalogs, registry/CDN responses and ATC delivery do not separately authorize code, measurements or serving keys. Delivery can withhold service and expose traffic metadata. Signed roots and fresh appraisal constrain what can be accepted. Freshness lasts seven days with five minutes of future skew; a still-endorsed older release is allowed. This is neither immediate revocation nor a newest-release guarantee. [Artifact authentication](../packages/tinfoil/src/public-build.ts), [freshness verification](https://github.com/tinfoilsh/tinfoil-go/blob/23734b7c6b9acf5359087412b03ebb524c2fb2f1/verifier/provenance/freshness.go).

## Plaintext, keys and runtime

The intended remote plaintext closure includes the measured kernel/PID 1, boot service, shim, container manager, rootful Docker/containerd/OCI runtime, NVIDIA driver and helpers, and the authenticated inference engine and its libraries/tokenizer/templates. Privileged guest code belongs inside this trusted software closure: mode `0700` does not exclude a root-capable process. One engine container and no sidecar or decrypting router are admitted by the configuration profile. [Runtime constraints](../tools/tinfoil-public-build/runtime.go), [service startup](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/pid1/main.go), [private/public paths](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/boot/paths.go).

The checked guest generates a fresh P384 TLS key and a new HPKE identity in its private RAM filesystem at boot. The HPKE file is reused within that boot, not provisioned across workers. The private tree, Docker data and containerd state are RAM-backed; the public container mount excludes serving keys. There is no profile-authorized vault/KMS/key export recipient. Future authenticated releases are trusted to preserve this custody contract; hashes authenticate the selected implementation, while publisher trust supplies its behavior. [Identity generation](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/boot/identity.go#L26), [RAM setup](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/pid1/runtime/setup.go#L125), [Docker state](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/image/rootfs/etc/docker/daemon.json), [containerd state](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/image/rootfs/etc/containerd/config.toml).

The signed deployment subject must equal the CPU-accepted signed predicate. Authenticated guest/configuration roots, recomputed RTMR1/RTMR2, the exact non-debug command line and the constrained runtime select the serving environment. The read-only guest and two model packs use dm-verity; the engine uses its authenticated OCI digest. Runtime downloads must obey those roots. Model attribution here means publisher-authorized model/tokenizer bytes, not proof that Google originally uploaded them. [Subject binding](../tools/tinfoil-public-build/release.go), [boot calculation](../packages/tinfoil/src/boot-measurements.ts), [guest mount](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/initrd/main.go#L67), [model mounts](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/boot/models.go#L83).

The production container manager opens no configuration replacement listener and records a one-shot boot marker. The shim enables inference only after boot succeeds. Modules cannot be loaded or unloaded after initialization. The engine has read-only root, dropped capabilities, bounded RAM caches and no external network; the shim dials fixed address `172.31.255.2`, without DNS. The guest's egress-capable services remain trusted guest processes. Request/output logging flags and remote-code loading are rejected by the profile. [Container manager](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/containers/main.go#L68), [shim gate](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/shim/main.go#L110), [module lock](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/pid1/hardening/module_lock.go), [upstream](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/shim/upstream.go), [closed network](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/internal/containernet/network.go), [egress](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/tinfoil/cmd/egress/main.go#L42).

The production kernel build selects a null console and disables virtual/serial consoles. Private guest logs are not made confidential merely by sanitizing errors. The claim depends on this console/build contract and the absence of an admitted transcript-export sidecar. [Kernel selection and config check](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/nix/kernel.nix#L12), [production console](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/kernel/config.d/20-production-console.config), [serial exclusions](https://github.com/tinfoilsh/cvmimage/blob/a4dbce07f5b0efbee1df678026db538eba66a613/kernel/config.d/20-console-common.config).

## GPU channel and reset contract

Fresh CPU report data authenticates the exact GPU evidence and serving public keys. The client locally verifies NVIDIA's report and requires one Hopper device in authenticated SPT mode. Driver/VBIOS upgrades require matching signed golden references, revocation checks and minimum versions `595.71.05` / `96.00.D9.00.02`; these numeric floors do not claim every newer version is vulnerability-free. [Appraisal](../packages/tinfoil/src/intel-appraisal.ts), [version policy](../packages/tinfoil/src/gpu-policy.ts), [mode interpretation and signed-field negative](tinfoil-gpu-runtime.md).

NVIDIA's manufacturer contract supplies SPDM authentication, protected CPU–GPU transfers, key isolation, reset/scrubbing and persistence semantics. The checked driver authenticates SPDM, derives channel keys, encrypts/authenticates UVM bounce transfers and enters a fatal state when the channel fails. Readiness cannot be restored after that failure; the guest module lock prevents recovering by reloading the driver. A new guest boot generates new serving keys and needs new client appraisal. These are manufacturer/publisher implementation contracts supported by source and signed live evidence, not measurements of a physical reset or every CUDA transfer. [Driver/source trace](tinfoil-gpu-runtime.md#driver-execution-and-failure-paths), [NVIDIA protected transfers, pages 11–13](https://docs.nvidia.com/nvidia-secure-ai-with-blackwell-and-hopper-gpus-whitepaper.pdf), [NVIDIA reset/persistence, page 28](https://images.nvidia.com/aem-dam/en-zz/Solutions/data-center/HCC-Whitepaper-v1.0.pdf).

## Client session and limits

Before an inference send, an owned session binds canonical model, authority-policy digest, authenticated release/artifact digests, current freshness bounds and the quote-bound TLS/HPKE keys to the transport. TLS 1.3 SPKI is checked on the actual socket before credentials or EHBP ciphertext. The direct transport sends once, rejects rotation/reconnect/fallback and uses a fresh encrypted cache salt. Streaming output and tool calls pass authenticated decryption with bounded bodies. [Transport](../packages/tinfoil/src/direct.ts), [TLS binding](../packages/core/src/pinned-tls.ts), [payload boundary](../packages/core/src/transport.ts).

The local cache retains authenticated immutable artifacts and deterministic verifier results, not CPU challenges, GPU verdicts, endpoint keys or freshness acceptance. Each dispatch obtains fresh evidence. [Cache regression](../tests/public-build-chain.test.ts). The actual production Pi suite and separate live-delta cancellation passed using default routing and the verifiers installed by the isolated tarball setup command. The candidate harness remains a separate adapter test. [Observed results](public-profile-validation.json), [harness](../scripts/live-pi.ts).

This is a contract for these provider dispatches. Whole-session protection remains unestablished because other providers, extensions, tools, compaction and fallback need Pi-level enforcement. Availability, traffic analysis, billing truth, output correctness, undocumented side channels and local-machine compromise are outside the claim. NEAR has separate deployed shared-key/session/KMS/runtime gaps. [Pi and NEAR boundaries](design.md).

`closedTrustSet: profile-declared` identifies this declared publisher/manufacturer closure. It does not claim an independent proof that every accepted software release behaves safely. New protocol/schema fields or GPU families outside the constrained profile require a client policy update; an authenticated compatible artifact update does not.
