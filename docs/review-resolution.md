# Pi TEE provider design: Opus review resolutions

Date: 2026-10-06. Author: Codex. [Revised design](design.md). [Independent Opus 5.5 review](design-review.md), completed by Opus 5.5.

The assessment/design is complete. Basic provider integration can be implemented as extensions. Production Approved workloads remains gated for both services until a specific deployment satisfies the stated evidence and enforcement requirements. This resolution records design changes, not implementation or security-test results.

| Finding | Resolution in the design |
| --- | --- |
| H1: Tinfoil automatic re-attestation/resend | Strict transport bypasses `SecureClient.fetch`, using verified bundles, exact independent approval, and a lower-level encrypted transport. Rotation requires approval before another send. Add rollback floors and the unapproved-rotation test. SDK-policy rotation reporting is explicitly post-hoc. |
| H2: SDK properties overstate verification | Fixed not-established disclosures cover full NEAR measured boot, CPU/GPU association, worker identity, key custody, runtime integrity, revocation, and rollback. Strict admission requires raw evidence and independent appraisal. |
| H3: missing trust actors | Name Tinfoil hardware references, credential-dependent sidecars, update controls, and delivery proxies; NEAR runtime package/model bytes, privileged processes, key derivation, OHTTP, recipe writers, and manager token holders. Enumerate these for each deployment rather than asserting an exhaustive production inventory has already been obtained. |
| M1: session-wide dispatch | Limit provider packages to their own requests. Protected sessions require a fail-closed guard after physical routing, covering switching, fallback, retries, and summaries. Selection reversion/context stripping alone is not the security boundary. A generic core hook is a concrete contribution candidate. |
| M2: retries | Zero provider retries plus a guarded stream wrapper with fixed terminal errors for security/integrity/ambiguous-execution failures. Test turn and summarization retry layers. Prefer a typed non-retryable contract upstream. |
| M3: runtime/body/header behavior | Qualify Node 24 initially; detect and probe actual Node/Bun capabilities. Helpers declare whether they receive plaintext. Return response headers promptly, buffer/verify signed body bytes before releasing them, bound memory/time, and test pinned SDK timeout behavior. Allowlist outer headers and transport overrides. |
| M4: catalogs | Use native refresh/publication/storage rather than timers. Keep an explicit refresh command and cover first-run/headless behavior. Refine the proposed freshness implementation as described below. |
| M5: first strict target | Prioritize a reachable direct Tinfoil worker, conditional on platform, custody, revocation, model-byte and GPU-path appraisal. NEAR proof of concept establishes missing server contracts; it does not enable a production profile from the inspected recipe. |
| M6: TLS exporter | Adopt as a proposed backend contract. The measured TLS terminator computes the actual connection's exporter; a quote over a caller-supplied value is insufficient. Bind protocol/nonce/policy too. Preserve separate mutation, forwarding, and application-key requirements. |
| M7: negative tests | Add evidence relay, old signed release, unapproved key rotation, both retry layers, cross-provider dispatch, runtime/configuration drift, hardware-reference drift, full TDX measurements, GPU topology, header/override leakage, and runtime capability tests. |
| Low: citations and key coverage | Correct the Sigstore policy reference and include OHTTP in the key inventory. Do not inherit the existing extension's stale comment suggesting the JS verifier lacks local AMD chain validation. |

Two review recommendations needed refinement after inspecting the source. First, `createProvider` persists `checkedAt: Date.now()` after every successful `fetchModels` return. Returning cached models for a four-hour freshness check would continually move that timestamp. The revised design uses a full native `refreshModels(context)` publication when skipping fresh entries or handling ETags, preserving the timestamp unless actual revalidation occurs. [Helper persistence](https://github.com/earendil-works/pi/blob/eb326d265ae0b88489a6d10319307780df827cdf/packages/ai/src/models.ts#L1108), [native freshness/publication example](https://github.com/earendil-works/pi/blob/eb326d265ae0b88489a6d10319307780df827cdf/packages/coding-agent/src/core/remote-catalog-provider.ts#L78).

Second, context redaction and selection reversion do not establish enforcement after physical routing. The design requires proof of dispatch coverage before claiming protected-session behavior, rather than assuming those extension hooks cover every fallback. [Caught request-hook exceptions](https://github.com/earendil-works/pi/blob/eb326d265ae0b88489a6d10319307780df827cdf/packages/coding-agent/src/core/extensions/runner.ts#L1361), [virtual routing](https://github.com/earendil-works/pi/blob/eb326d265ae0b88489a6d10319307780df827cdf/packages/coding-agent/src/core/virtual-models.ts).

The reviewer also corrected its certificate-archive claim on request: unauthenticated AES-256-CBC does not establish archive integrity or anti-rollback. The corrected independent report and the design both require separate authentication and rollback enforcement before treating S3 as delivery-only. [Archive crypto implementation](https://github.com/nearai/cvm-ingress/blob/c785c6ed8d4ec0bb0ec4bcb45ef7afe3de48b24e/lib/crypto.sh).

Opus reviewed the initial design and source snapshots; Codex reconciled the resulting changes. This is not a claim that Opus performed a second complete review of the revised document.
